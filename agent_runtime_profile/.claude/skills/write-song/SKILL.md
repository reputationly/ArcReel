# 写歌：曲风描述与歌词

ACE-Step 是 **caption + lyrics 双输入**模型：描述决定曲子长什么样，歌词决定唱什么。
本 skill 只产出这两样文本，**不调用作曲工具**——作曲走 `generate-music`。

## 工作方式

用户给方向或初稿 → 你优化 → **交用户确认或修改** → 定稿后才作曲。

不要拿自己的版本直接开工。歌词是 MV 的骨架，用户改一个字都可能要重排镜头，
所以定稿必须由用户点头。

## 曲风描述（prompt）怎么写

四要素齐全，逗号分隔的短语，别写成句子：

```
风格 + 情绪 + 乐器 + 节奏
```

好的例子：

```
indie folk, melancholic, acoustic guitar and soft strings, 70 BPM, female vocal
城市民谣，怀旧克制，木吉他与钢琴，中慢板，男声
```

坏的例子：

```
一首很好听的歌                        ← 没有任何可执行信息
我想要那种听了会哭的感觉，就像失恋一样   ← 全是感受，没有音乐要素
```

要点：

- **具体乐器名比抽象形容有用**：写「木吉他 + 弦乐」而不是「温暖的编曲」
- **BPM 给个数**：慢 60-75、中 76-108、快 120+
- **人声性别与音色**写进描述（female vocal / 低沉男声），它影响演唱效果
- 中英文都能用，但**同一段描述别混写**

## 歌词怎么写

### 用结构标签分段

ACE-Step 按标签识别段落，标签决定旋律走向：

```
[intro]

[verse]
第一段主歌，铺陈画面
每行短一些，别写成长句

[chorus]
副歌，最想让人记住的两三句
可以重复

[verse]
第二段主歌，推进叙事

[chorus]

[bridge]
桥段，情绪转折

[outro]
```

常用标签：`[intro]` `[verse]` `[chorus]` `[bridge]` `[outro]`。

> 标签是 ACE-Step 的通用惯例，本仓库的门面契约里没有对它做校验或转换——
> 若实测发现引擎对某个标签不响应，改用最基础的 `[verse]` / `[chorus]` 组合。

### 写作要点

- **每行短**：一行对应一个乐句，长句唱不下、也不好卡镜头
- **副歌重复**：重复是记忆点的来源，不要每段都写新词
- **具象优于抽象**：写「凌晨四点的便利店」而不是「孤独的感觉」
- **避免生僻字与多音字**：歌声合成对它们的发音不稳
- **段落数量与目标时长匹配**：3 分钟的歌大约 2 段主歌 + 2 次副歌 + 1 个桥段

### 留空歌词会怎样

不传歌词时引擎会**自己作词**（sample 模式，按描述用 LM 生成）。
纯 BGM 项目这样最省事；**MV 项目不要这样**——引擎自编的词与剧本里排好的
`lyrics_line` 对不上，镜头逐句对歌词，错一句后面全错。

## 交付

产出这两段文本给用户确认。用户改完后：

- **MV 项目**：歌词经 `mcp__arcreel__patch_song({"script": "episode_1.json", "lyrics": "..."})`
  写进剧本，再走 `generate-music` 作曲（把同一份歌词传给 `lyrics` 参数）
- **其他项目**（纯 BGM）：直接走 `generate-music`，不必写进剧本

## 边界

本 skill 不作曲、不改剧本镜头。写完文本就停下等用户确认——
擅自往下走会让用户在没看过歌词的情况下就产生了作曲费用。
